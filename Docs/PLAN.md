# MetaGen 自动生成全部 Object 派生类的 C# Binding

## 目标与约定

覆盖所有继承自 `Orbeden::Object` 的 C++ 类，包括组件、资源和游戏脚本。新增符合导出规则的 C++ 类后，构建自动生成 C# 包装、原生调用入口和工厂注册，不再逐类型手写 Binding。

已确定：
- 默认导出可绑定的 public 字段和方法；内部成员显式排除。
- C# 类名、成员名跟随 C++，同步修改仓库调用方，不保留旧名称兼容层。
- 序列化与 Binding 分别描述；private 序列化字段不自动公开。
- `Object`、`Component`、`Script` 保留必要的手写运行时基础逻辑，通过 `partial` 与生成部分组合。
- GUI、输入等非 Object API 不在此次自动生成范围内。

## 生成规则与调用机制

- 将 MetaGen 改为“解析公共模型 → 分别生成反射和 Binding”。保留现有 .NET 工具链，使用词法扫描处理声明、命名空间、继承、重载和默认参数，避免目前正则解析对不支持成员的静默遗漏。
- 为 Core 生成类型清单，游戏模块解析时导入，正确识别跨模块基类与成员类型。
- 添加显式元数据：排除成员、指定属性 getter/setter、声明指针与长度组成的缓冲区参数。不猜测 setter 的副作用。
- 支持基本数值、枚举、字符串、引擎数学类型、Object 引用、`Ref<T>`、值结构及其数组；数组读取得到快照，写入复制回原生。指针缓冲区生成 Span 接口，禁止把原生临时内存直接暴露给 C#。
- 不支持的公开签名报出文件、成员及原因，要求显式排除或调整接口。模板成员、运算符及内部生命周期钩子不自动导出；现有公开业务能力必须完成迁移，不能通过排除来丢弃。
- 输出 C++ 类型化调用入口、C# `partial` 类和模块注册清单。普通调用直接使用缓存函数指针，不经过字符串查找或通用 `InteropValue` 装箱。
- 通过公共 Binding 注册接口连接 Core、Editor DLL 和 Player 静态模块；使用类型与签名校验生成物一致性，不将运行时 TypeId 固化进生成源码。同步更新 ABI 版本和布局检查。
- Core 包装置于 `Orbeden`，游戏包装置于项目的 `Native` 子命名空间；保留 C++ 类名并映射其子命名空间，避免与手写 C# 游戏脚本撞名。

## 对象身份、工厂与 Script

- 用生成的类型注册表替换 `Ens` 中逐类型的创建、查询和包装判断。按实际原生类型选择包装工厂；经基类查询返回派生包装，保持同一原生实例的包装身份一致。
- 组件统一通过 `Ens.AddComponent<T>()` 创建；非组件运行时对象通过 `Object.CreateInstance<T>()` 创建，资源通过 `Resources.Load<T>(key)` 加载。抽象类型只能查询，不能直接创建，沿用现有原生所有权规则。
- 游戏原生 Binding 和手写托管脚本明确分类，不能再仅凭 `IsAssignableFrom(Script)` 判断执行域：
  - 已注册的原生类型：创建对应 C++ 实例，只参与 Native 生命周期。
  - 手写托管 Script：创建精确原生 Script 宿主，只参与 Managed 生命周期。
- `Script.Generated.cs` 提供普通绑定成员和原生包装构造入口；`Script.cs` 保留托管构造上下文。生成的原生脚本包装可继承 `Orbeden.Script`，但不会作为托管脚本启动。
- 同步修改 Inspector、依赖检查、程序集扫描和字段元数据，排除生成包装的托管脚本注册，避免菜单重复和双重生命周期。
- 本次不支持通过继承生成包装来向 C++ 类型追加托管生命周期；这种声明明确报错。手写托管脚本之间的继承继续支持。
- 模块卸载前注销工厂、函数入口及托管类型引用；旧包装与缓存通过 generation 失效，禁止调用已卸载 DLL 的地址。

实施时首先创建 **`Docs/AutoBindingsTODO.md`**。每项记录状态、相关修改、验证命令及结果；暂停时写明准确的下一步和阻塞项，不依赖聊天记录恢复进度。

- [ ] **阶段 0：清点与验收基线。** 列出全部 Object 派生类、现有 Binding API 和业务副作用，建立逐项迁移表，保留当前工作区修改。
- [ ] **阶段 1：生成器。** 完成公共类型模型、导出标记、类型转换及 C++/C# 输出；用最小样例验证继承、字段、重载、引用和数组。
- [ ] **阶段 2：公共运行时。** 接入 Binding 注册表、对象工厂、身份缓存和失效机制；用 Collider 与原生 Script 打通真实创建、调用和销毁。
- [ ] **阶段 3：全部组件迁移。** 迁移 Transform、渲染、物理等组件；显式排除内部状态，将属性写入连接到正确 setter，移除已被替代的手写表与分派。
- [ ] **阶段 4：全部资源迁移。** 迁移 Mesh、Material、Shader、Texture2D、Skybox 等；保留加载、数组传输、对象引用和脏标记行为。现有桥接层中的类型专属业务移入对应 C++ 类，供生成入口调用。
- [ ] **阶段 5：构建与游戏模块。** Core、游戏 CMake、C# 构建及 AOT 发布均先执行生成；C# 独立构建也能取得最新包装源码。生成清单管理过期产物，避免扫描构建目录或并行写入同一输出。
- [ ] **阶段 6：调用方和最终清理。** 更新 Editor、模板、测试和文档；模板 HUD 改用生成的原生脚本包装。删除已替代的逐类型 Binding，不保留自动调用失败后转回旧实现的路径。

阶段之间允许暂时存在尚未迁移的类型；同一类型完成迁移时立即移除旧路径。最终验收必须覆盖全部 Object 派生类。

## 验证与完成标准

- **生成器：** 输出确定且重复运行无差异；支持新增、删除、重命名类型；覆盖跨模块继承、访问级别、重载、默认参数、枚举、结构、字符串、数组和错误诊断。
- **组件与资源：** 验证新增组件无需手写 C# 即可创建、查询和调用；覆盖 Transform 通知、物理属性生效、Mesh/Shader/Material 脏标记、资源引用及回收。
- **Script：** 验证原生派生 TypeId 保持独立；原生包装不进入托管调度；托管脚本仍正确执行 Start/End，重入、异常、禁用和销毁行为保持正确。
- **生命周期与重载：** 覆盖多实例、基类查询、包装身份、对象删除、原生模块重载、CLR 程序集卸载和旧句柄拒绝调用。
- **端到端：** 构建原生及托管 Core/Editor；运行模板回归；完成 Windows x64 NativeAOT Player 构建与启动验证。
- **最终完成：** 迁移清单全部验收，新 Object 派生类不需修改中央分派代码；所有生成范围内的旧手写 Binding 已删除，文档列明 API 命名变化与外部项目重建要求。
