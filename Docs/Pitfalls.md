# 渲染

## 坑 1：外空间看星球，地平线上有一条深色细线（"黑线"）

**现象**：海平面（尤其相机低于海平面时）望向水平线，地平线上出现 1~2 px 的深色细线。相机越低越明显，抬高会淡化。外空间看星球边缘时也有同样形态的一条。

**指纹**：
- 颜色是**天空色被整体压暗**——三通道同比例下降（实测约 45%），不是某个通道被抹掉。这一条能把它和"下溢/精度"类故障区分开：那类故障的颜色会明显偏色。
- 位置恰好在地平线（`mu == muHorizon`），不是偏移一两像素。
- 相机越低越深；低于海平面时最深（此时"地平线以下"的值恰好是 0）。

**成因**：天空查找表在跨地平线处被**一次双线性取样**读出来，而地平线两侧的值差别极大：以上是掠射整层大气的辉光（亮），以下是最多几公里的近地散射（暗，相机低于海平面时按 `groundHeight = max(h,0)` 的约定恰好为 0）。平均值哪一侧都不代表。同时地面底板的覆盖率过渡带**从地平线向球内单边展开**（`smoothstep(0, w, d)`），界线那一像素的覆盖率为 0——本该由底板顶上的那半个像素，正好被留给了这个谁都不代表的混合值。

**修法**：
1. 地平线两侧的采样坐标**分开取**，各自夹到 `0.5 ∓ 0.5/height`（即各自一侧那一行的中心），不让表跨边界混合；再由地面覆盖率在"地面（含底板）"与"天空"之间混合。
2. 覆盖率过渡带**以地平线为中心**（`smoothstep(-w/2, +w/2, d)`），而不是单边展开。

**教训**：低分辨率表的双线性插值不承认硬边界——**跨边界的混合值是一个不存在的颜色**，而贴着边界的像素会把它当真值显示出来。凡是边界两侧的物理量差别大（差几倍甚至一个量级），都必须把两侧分开取。

## 坑 2：地平线或星球边缘出现亮线／成串亮点（"亮线"）

**现象**：贴着地平线一条亮线；修掉之后变成沿弧线断续的亮齿（每个齿约 1 px，间隔几个像素）。夜面星球边缘最明显——那里亮环对纯黑，反差最大。

**指纹**：
- 颜色是**地面底板的颜色**（相机 clearColor 的色调，实测 `(127,149,170)`，与底板在别处量到的 `(160,180,200)` 同色调浅深之差），出现在本该接近全黑的地方。**它的颜色是对的，权重是错的**——这一条能和"查找表串色"类故障区分开。
- 只出现在跨地平线的那一两个像素上（抗锯齿过渡带内）。
- **关掉 Atmosphere Fog 与 Dense Fog 依然存在**——说明与雾无关，只可能在天空/底板合成里（这是把范围缩到最小的关键实验）。
- 相机在大气外时表现为整条线；在大气内低空时表现为断续的齿（齿的位置由过渡带与像素网格的相位决定）。

**成因**（同一个颜色的两次权重错误）：
1. 底板的透光率原本用"透射率表两次采样相减"求：近地平线方向两端 τ 都很大（掠射红约 24、绿约 56、蓝可到几百），而需要的是它们之间**不到 1** 的差；半精度表在 τ≈287 处的 ulp 就有 0.25，这个差根本表示不出来（再叠加 `outTau = min(tau, 20)` 的钳位，两端直接都变成 20，差恒为 0）→ 底板透光率被算成 ≈1（本该 ≈0）。
2. 修正之后仍有齿：`IntersectGroundDistance` 在射线没打到地球时返回负值，函数提前返回，而 `transmittance` 还停在初始值 **1.0**，合成时照常按覆盖率参与 → 底板按"无衰减"整块叠上去。

**修法**：
1. 这一小段不走表：相机在大气外时沿视线查**一次**透射率表（单次插值，没有相减）；相机在大气内时对"地面→相机"这一小段**直接在射线上积分 4 步**（段一长 τ 就远大于 1、透光率必然是零，定点几步足够；段短时沿线高度变化极小，中点采样已经够准）。
2. 求交前把方向**夹到地平线以内**（`mu ≤ muHorizon − 1e-6`），拿到掠过地平线那条的透光率；覆盖率恰好为 0 的像素提前退出，保持开销不变。

**教训**：
- 任何"**两次查表相减／相除**"的写法，先问这个差在表的精度里表示得出来吗。比它更根本的替代是绕开表、直接在着色器里积分。
- **`out` 参数里的默认值不是中性值**。缺失时返回 1.0（或任何"看起来无害"的值）会被后续合成当成真值用，而且只在部分像素上生效，看起来就像随机噪点。宁可显式判空并传 0。

## 通用教训（渲染）

- **数学上连续，不等于量化之后看不见。** 判断某个量会不会出瑕疵，看的是它在**一格之内的相对变化**，不是它是否连续。掠过球壳切线时弦长连续趋于 0，但 √ 形状的陡升在低分辨率表里照样被重建成台阶。
- **屏幕空间的表放不下与视口无关的结构。** 地平线在屏幕上是圆弧，用屏幕坐标存储的查找表无法把量化方向对齐到它——外空间看到的那条弧线会被量化成屏幕轴对齐的台阶。改成方向空间、并让地平线落在节点行边界且靠地平线加密之后，量化步长才跟着弧线走。
- **定位手法：先量像素，再改代码。** 两个高识别力指纹：边缘位置的**周期**（2 px = 着色器 quad、约 9/12.6 px = 查找表节点、1 px = 逐像素偏移）与跨边缘的**颜色**（哪个物理量被错误代入）。
- **一次只改一个成因。** 同一现象背后可能压着多个独立原因，修掉一个下一个才露出来；混在一起改就分不清是哪一半起了作用。
